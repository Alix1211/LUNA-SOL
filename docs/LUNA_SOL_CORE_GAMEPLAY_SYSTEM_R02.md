## 0. 설계 오류의 공식 기록

지금까지 EP001~EP090 실제 대본과 총 270개 내외 머지 미션이 먼저 작성됐다. 그러나 **시나리오 분량이 게임의 장기 플레이 시스템을 대신하지 못한다.**

- **잘못된 흐름:** 대사 발생 → 특정 물건 제작 지시 → 납품/복원 → 다음 대사 → 다음 지정 미션.
- **올바른 흐름:** 플레이어가 자유롭게 생산·합성·배치·돌봄·거래를 반복 → 공간·생활·드래곤이 실제로 성장 → 그 결과로 캐릭터·장소·사건이 조건부 등장 → 퀘스트를 진행하거나 미루더라도 게임 시스템은 작동한다.
- **치명적 금지:** 「N화 클리어를 위해 의자 제작을 강제」, 「N화 클리어를 위해 탁자 제작을 강제」를 90회 반복하는 구조.
- 대본의 270개 머지 미션은 **세계관 사건에 필요한 제작 제안·스토리 임무 후보**로 재분류한다. 이를 자동으로 플레이어의 필수 작업 큐로 생성하지 않는다.
- 퀘스트가 1명만 있거나 모두 종료되어도 복원·경제·드래곤 육성이 서로 맞물려 계속 흥미롭게 돌아가야 한다.

## 1. 사용자가 지정한 게임의 중심축 (확정)

### 1-1. 공간을 하나씩 완성하는 복원·꾸미기

1. **방 내부:** 기본적인 의자 → 탁자 → 침대 → 옷장·조명·커튼·장식 같은 실제 생활 가구를 **플레이어가 직접 제작·설치**한다. 이것은 튜토리얼 예시일 뿐, **모든 플레이어가 반드시 그 순서를 강제당해야 한다는 뜻은 아니다.**
2. **집/성 내부:** 침실, 거실, 부엌, 작업실, 저장실, 드래곤 보금자리, 복도, 정원 등 공간이 **기능과 외형을 갖추면서** 확장한다.
3. **마을:** 이웃집, 공방, 가게, 광장, 길, 공공 시설을 하나씩 복원하고 주민이 돌아와 이용한다.
4. **왕국:** 숲, 광산, 항구, 북방 등 새로운 지역이 열리면 지역마다 공간의 성격에 맞는 복원과 일상 기능이 추가된다.
5. **완공 결과는 영구적이고 가시적이어야 한다.** 단순 배경 CG 한 장 교체 또는 복원 퍼센트 +10으로 끝나지 않는다. 가구 위치·외관·사용 행동·생산 기능·방문객·주민 활동이 변한다.
6. 배치·교체·꾸미기를 별개 재미로 보장한다. 설치한 가구는 소유·재배치·교환·업그레이드가 가능해야 하며, 안전 장치가 있는 한 실수로 고유 물품이 사라져서는 안 된다.

### 1-2. 드래곤 육성은 필수 주력 시스템

- 드래곤은 퀘스트의 이벤트 컷신이나 해금 보상만이 아니라 **평상시에도 돌보고 관찰하는 생활 동반자**다.
- 개체별 성장 단계, 성격, 선호, 먹이, 기분, 친밀도, 휴식, 놀이, 행동 애니메이션, 자신만의 숙소가 필요하다.
- **드래곤을 기르는 재미가 드래곤의 마력을 얼마나 뽑아 쓰느냐로 환원되면 안 된다.**
- 새 드래곤이 등장하면 장기 플레이에 실제 생활·돌봄의 다양성이 증가해야 한다. 여덟 수호룡의 서사 역할과 플레이어가 일상적으로 돌보는 어린 드래곤의 상태를 구분한다.
- 이전 R01의 **알 → 유체 → 성장체 → 성체**는 현재 성장 표현의 초안이며, 실제 성장 요구량·속도·행동 세트는 추후 설계·검증해야 한다.
- 돌봄은 중요하지만, 현실 시간 강제 출석·무한 대기·벌점·방치 사망처럼 플레이어를 피곤하게 하는 방식은 금지한다.

### 1-3. 세 가지 경제·플레이 축

**A. 공간 복원/인테리어 / B. 생활 생산·주문·거래 / C. 드래곤 숙소·용품·먹이·교감**

세 시스템은 독립적으로도 플레이 가능하지만 재료·수익·해금·일상 이벤트를 통해 연결된다. 어느 하나가 시나리오 중단 때문에 멈추지 않는다.

## 2. 머지 보드 구성 (방향 제안, 세부 확정 전)

| 보드 | 대표 생산기 | 합성·제작 계열 예시 | 최종 사용처 |
|---|---|---|---|
| **건축·인테리어 보드** | 목재 작업대, 재봉 바구니, 석재 수레, 금속 공구함 | 의자·탁자·침대·옷장·조명·바닥·벽장식 | 가구 실제 배치, 집·마을 복원, 기능 시설 |
| **생활·경제 보드** | 밭, 식재료 바구니, 약초 바구니, 가마솥, 상점 생산기 | 식재료·음식·약품·공방 상품·생활용품 | 주민의 반복 주문, 거래, 자금 확보, 시설 유지·확장 |
| **드래곤 전용 보드** | 둥지 제작대, 먹이 조리대, 놀이 상자, 관리 도구함 | 숙소·둥지·방석·침대·먹이·간식·장난감·목욕·손질·안전시설 | 드래곤 거처 꾸미기, 일상 돌봄, 교감·성장 |

**주의:** 3개의 머지 보드를 **분리할지, 공통 보드와 탭으로 분기할지, 보드별 크기·에너지·생산기 레벨을 어떻게 할지**는 UX·기기 성능·플레이 테스트 후 결정한다. 위 표는 **제작 계열의 논리적 분리**를 뜻하며, 화면 3개를 무조건 구현하라는 명령이 아니다.

### 2-1. 드래곤용 전용 머지 계보 예시

| 생활 분류 | 저단계 | 중간 단계 | 상위 단계 및 용도 |
|---|---|---|---|
| 숙소 | 짚자리·천 조각 | 방석·포근한 둥지 | 장식 둥지·개별 드래곤 하우스 |
| 식사 | 열매·생선·채소 | 과일 접시·영양식 | 선호 간식·특별 식단 |
| 놀이 | 깃털·공 | 움직이는 장난감 | 드래곤별 놀이기구·놀이터 |
| 위생/관리 | 수건·물그릇 | 목욕 세트·손질 도구 | 개별 관리실·휴식 시설 |
| 환경 | 작은 화분·이끼 | 그늘막·보온대 | 속성·성격에 어울리는 전용 서식 환경 |

- 아이템이 희귀할수록 무조건 '더 좋은 아이'가 되는 숫자형 육성만으로 끝내지 않는다. **숙소에 배치했을 때 행동 변화**, 선호 반응, 일상 이벤트, 편안함과 놀이 다양성이 있어야 한다.
- 드래곤별 선호를 모두 같은 숫자 부스트로 일괄 처리하지 않는다. 니베가 좋아하는 둥지와 다른 드래곤이 선호하는 환경은 다를 수 있다.
- **살아 있는 드래곤, 수호룡, 계약 의사, 생명력은 머지 재료가 아니다.** 알이나 핵심 서사 유물 또한 일회성 합성 재료로 임의 소모하지 않는다.

## 3. 시나리오가 없어도 돌아가는 실제 게임 루프 (반드시 구현)

### 3-1. 공간 복원 루프
자발적 목표 선택 → 재료 생산·합성 → 가구 완성 → **공간에 실물 배치** → 공간의 외형·기능·주민 행동 변화 → 새로운 꾸미기 선택/공간 확장.

### 3-2. 생활·경제 루프
재료 생산 → 물건 합성·가공 → **주민 주문·판매·거래** → 골드·재료·시설 경험 축적 → 생산기·보관함·공방·상점 개선 → 새로운 제작 계열/주문.

### 3-3. 드래곤 육성 루프
숙소·먹이·용품 제작 → 드래곤별 거처 설치·돌봄·놀기 → **기분·친밀도·행동·성장 상태 변화** → 새 행동·시설·꾸미기 방식 개방 → 자발적 일상 상호작용.

### 3-4. 이야기/퀘스트 루프 (부가)
플레이어의 **공간 복원·새 주민 유입·시설 완공·드래곤 관계·지역 개방** 등이 충족 → NPC 등장·사건의 단서 발생 → 플레이어가 이야기를 보고 선택적으로 따라감 → 새 지역·도구·인물·생활 요소가 열림 → 기본 시스템은 그대로 지속.

**검수 질문:** 지금 모든 스토리 대본과 퀘스트 제공자를 제거해도 플레이어가 30분 이상 재미있게 할 선택과 성장이 남는가? 단순 클릭 반복이 아닌 실제 경제·배치·성장 결정을 내릴 수 있는가?

## 4. 제작 결과물은 시각적·기능적으로 남아야 한다

| 제작/복원 | 즉각 시각 변화 | 실질적인 후속 기능 (제안) |
|---|---|---|
| 의자 | 방 안에 실제 배치된 의자 | 인물·주민 앉기, 장식 취향 |
| 탁자 | 소품 올려놓을 표면 | 작은 물건·간식·화병 배치 |

| 공방 | 장비·작업대·직원이 보임 | 생산기 해금/업그레이드, 고급 가구 제작 |
| 정원 | 실제 나무·화단·분수 변화 | 식재·채집·가꾸기, 일상 방문객 |

**원칙:** 단순한 미션 체크박스, 상태 문구 한 줄, 배경 페이드 전환만으로 **복원 완료를 주장하지 않는다.** 공간에 계속 남는 변화와 놀이를 보여준다.

## 5. 오더/퀘스트는 무한 반복 플레이의 부속 요소

### 주민 주문
- 상점·공방·치료원·음식·가구 등 현재 개방된 생산 계열에서 주문 자동/조건부 생성.
- 납품 보상은 원가와 노력을 고려한 **골드·경험·재료** 등. 반복 가능하되 단조롭지 않아야 함.
- 주문 새로고침/거절, 난이도 범위, 보드 공간과 창고 관리, 진행 막힘 방지 로직 설계.
- **퀘스트 하나만 있는 테스트판처럼 스토리가 종료돼도 주문과 경제 시스템은 멈추지 않음.**

### 스토리 퀘스트
- EP001~EP090의 역사·인물·복선·결말을 훼손하지 않고, **공간·성장 조건을 충족한 후 자연스럽게 활성화**한다.
- 기존 대본의 M001~M237 등 미션 번호와 수량은 **서사 이벤트 목록**으로 보존하되, 현행 시스템의 필수 제작 순서를 뜻하지 않는다. **임의 재번호 부여·삭제하지 말 것**.
- 어떤 스토리 대사가 '이것을 만들어야 다음 이야기가 열린다'고 쓰여 있더라도 실제 게임에서 그 물건이 **공간을 위해 필요한 것인지, 캐릭터가 일방적으로 지시하는 심부름인지** 재검토한다.
- 필수 스토리 진행이 필요한 경우에도 플레이어의 현재 복원 선택과 연결되는 자연스러운 조건으로 설계한다.
- 모든 콘텐츠를 완전 비선형으로 풀라는 뜻은 아니다. **서사상 고정 순서가 필요한 큰 사건과 드래곤 각성은 유지**하며, **일상 복원 순서는 폭넓게 자유화**한다.

## 6. 참조 게임 및 비교 기준

사용자가 직접 제공한 **Claude 협업작 \`merge_shop_테스트판.html\`**을 **게임 시스템 참고 자료**로 삼는다. 이 HTML은 퀘스트가 짧아도 게임 루프가 독립 작동한다는 점이 핵심이다. **파일의 일부·전체를 GitHub에 무단으로 복제하지 않는다.**

참고할 시스템 구조:
- 생산기 → 머지 → 주문/판매 → 골드 → 생산기·직원·상품 성장 → 새로운 주문의 선순환.
- 직원별 역할·성장에 따라 실제 주문·판매·기획 능력이 달라지는 점.
- 재화·아이템 고갈 시 진행이 영구히 막히지 않도록 하는 설계.
- 지속 저장, 보드/창고 관리, 반복 주문을 통한 자유 플레이.

외부 레퍼런스는 **Merge Mansion(복원과 머지), Travel Town(주문과 경제), Merge Dragons!(드래곤의 지속 성장과 공간 돌봄)**을 **시스템 비교 대상**으로만 활용한다. 검증 없는 수치·메커니즘은 사실로 단정하지 않고, UI/아트/상용 게임 자산을 복제하지 않는다.

## 7. 실제 플레이 장면 시뮬레이션

### 튜토리얼 다음 30분 (시스템 예시)
1. 플레이어가 성의 첫 방을 열고 **의자, 탁자, 침대 중 먼저 만들 가구를 선택**한다.
2. 머지 보드에서 재료를 합성해 의자를 만들고, 방 안에서 **위치를 직접 결정**한다.
3. 더 좋은 침대를 만들지, 다른 벽지·커튼을 만들지, 자원을 아껴 옆방을 열지 결정한다.
4. 생활 보드에서 작은 주민 주문을 납품해 골드를 벌고, 보관함을 확장한다.
5. 드래곤이 발견되었거나 부화한 시점이라면 드래곤 보드에서 둥지·먹이·장난감을 제작하고, 실제 돌봄 행동을 본다. **아직 드래곤이 없다면 이 기능이 '미해금'인 것이 정상**.
6. 방이 살아갈 만해지고 새로운 통로나 주민의 방문 조건이 성립하면서 **EP의 다음 사건이 발생**한다.
7. 플레이어는 이야기를 진행하거나, 가구를 교체하고 돈을 벌며 더 꾸미거나, 드래곤과 시간을 보낸다.

**시나리오 발생이 플레이어의 선택과 복원 성과를 따라온다.** 스토리 때문에 제작을 시작하는 경우가 있어도, 그것만이 게임의 유일한 목적인 구조는 금지한다.

## 8. 제작팀이 먼저 확정해야 할 미해결 설계 항목

다음은 아직 **확정되지 않았다**. 임의로 코드에 박아 넣지 말고 기획·테스트로 정한다.

1. 복원 공간의 종류·수·연결 지형과 개방 조건, 공간별 가구 슬롯·자유 배치 범위.
2. 세 제작 계열의 UX: 3개의 독립 보드인가, 공용 보드+탭인가; 보드 크기/공간 효율; 장기 보드 혼잡 대응.
3. 생산기 레벨, 아이템 단계, 생산 원가, 골드 밸런스, 주문 수량·시간 간격·새로고침.
4. 골드 외 자원 필요 여부와 창고 확장·보관·아이템 실수 복구.
5. 드래곤별 단계, 친밀도·기분 계산, 굶주림/피로 페널티 유무, 행동 애니메이션, 휴식과 교감의 빈도.
6. 부화·새 드래곤 등장 전후 기능 해금 순서(EP002 알, EP006 니베 부화와 모순 없게).
7. 공간 성장과 EP001~EP090 사건 간 상태 플래그·해금 지도를 만드는 데이터 모델.
8. 저장·백업/복구와 호환성, 상호작용 가능한 배치 시스템의 데이터 구조.
9. 오른손 검지 **단일 탭**을 중심으로 하는 선택·합성·배치·이동·수납 UI. 필수 드래그·핀치·멀티터치 금지.
10. 튜토리얼 종료 후 퀘스트 없는 상태, 자원 부족, 꽉 찬 보드, 드래곤 미해금 상태의 재미·복구 테스트.

**개인용 게임 공통 제약:** 판매·광고·과금·강제 출석·현실시간 기다림 강제 없음. 안드로이드 태블릿 가로 화면, 오른손 검지 한 손 조작, 자동 저장·백업/복구, 실수 복구.

## 9. 최종 승인 기준 · 작업 순서 교체

### 완료라고 주장하기 전에 반드시 통과할 시험
- [ ] 튜토리얼 이후 **퀘스트를 전혀 진행하지 않아도** 머지 생산/복원/배치/경제가 돌아간다.
- [ ] 첫 방에서 **의자·탁자·침대가 실제로 생성·배치되고 외형과 생활 기능에 차이**가 있다.
- [ ] 방 → 집/성 → 마을 → 왕국 확장이 단순 안내가 아닌 실제 플레이 가능한 공간 변화다.
- [ ] 주문·판매·성장·재화·창고·진행 막힘 방지의 장기 루프가 있다.
- [ ] 드래곤이 해금되면 **둥지·음식·놀이·관리용 머지 계열**을 활용해 실제로 교감하고 행동하며 성장한다.
- [ ] 스토리 대본이 0개여도 시스템이 재미있게 돌아가는 구조적 근거가 있다.
- [ ] 시나리오상 드래곤 강제 추출과 현실 게임의 드래곤 돌봄 시스템이 모순되지 않는다.
- [ ] 90화의 사건 인과·주요 복선·인물 관계를 손상시키지 않는다.

### 수정된 제작 순서
1. **이 문서의 시스템 방향 승인 기준으로 고정.**
2. 공간 복원/배치·생활 경제·드래곤 육성의 **상세 기획·데이터 구조·상태 플래그** 작성.
3. 퀘스트를 비활성화한 상태로 **독립 자유 플레이 버전** 제작 및 재미/진행 막힘 시험.
4. 실제로 재미있는 루프가 작동함을 확인한 후 **90화 시나리오를 공간·성장 조건에 매핑**.
5. 아트 통일·성능·접근성·저장 호환 검증, 전체 운영 및 엔딩까지 통합 테스트.

**작업자 주의:** 90화 대본 완료는 시나리오 초고 완료를 뜻한다. **게임 시스템 완성이 아니다.** 앞으로 시스템 검증 없이 '다음 퀘스트/다음 회차'를 대량 생산하는 일은 우선순위가 아니다.

## 10. R01에서 R02로의 교체 명시

| 구분 | 기존 R01 | 새 R02 적용 |
|---|---|---|
| 게임 중심 | 스토리 중심 머지 | **공간 복원·꾸미기·생활경제·드래곤 육성 중심** |
| 제작 이유 | 이야기가 요구하는 물건 | **플레이어가 원하는 공간·돌봄·경제 목표** |
| 퀘스트 역할 | 머지·복원 행동의 주 지시자 | **공간 성장의 결과로 열리는 사건과 추가 목표** |
| 게임 끝 | 90화 완료 시 주 활동 종료 위험 | **90화 이후에도 기존 시스템을 계속 즐김** |
| 드래곤 | 스토리 각성·핵심 캐릭터 | **일상 돌봄·육성·숙소·용품·개별 취향의 지속 콘텐츠** |
| 머지 | 스토리 미션 중심 | **건축·경제·드래곤 용품 계열이 독립적으로 순환** |
| 복원 | 수치·단계 표시로 끝날 위험 | **공간에 영구적 실물 변화와 기능** |
| 검증 | 회차·머지 미션 완료 | **퀘스트 없는 상태에서도 플레이 재미 검증** |
